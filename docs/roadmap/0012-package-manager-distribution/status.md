1. **Local-only UBSan false positive on an older toolchain - fixed (maintainer ruled "fix it now", 2026-11-16).** On a local `macos-asan` run with **AppleClang 14.0.0**, `smbios_c_typed_getters_test` aborted: `-fsanitize=function` reported "call to function `smbios_bios_vendor` through pointer to incorrect function type" at `tests/c_abi/smbios_typed_getters_test.cpp`.    **Diagnosis, corrected.** The first reading recorded here was that C++ language linkage made the `fetch()` helper's function-pointer type differ from the `extern "C"` getters. That was **wrong**: declaring the typedef inside an `extern "C"` block changed nothing, the identical error simply moved with the line. A minimal in-translation-unit probe (an `extern "C"` callee invoked through a pointer under `-fsanitize=undefined` on the same compiler) does **not** reproduce it either. The header declaration, the definition at `smbios_c.cpp:279` and the call site have character-for-character identical parameter lists, so there is no type mismatch to fix in this repository's code. It is a false positive from that Clang generation's prologue-hash implementation of `-fsanitize=function`, which cannot find a matching signature for a getter reached across `smbios_c`'s shared-library boundary (`CXX_VISIBILITY_PRESET hidden` plus the explicit `smbios_c.exported_symbols` linker allowlist - the arrangement milestone 0007 built deliberately).

The file's stale "Not wired into CMake yet" header comment was corrected - it runs in the C13 unprivileged set. Verified: `stage.py test --leg macos-asan` now reports `tests unprivileged: 18 passed, 0 skipped, 18 total` and `tests live-table: 3 passed` locally on AppleClang 14, matching CI. - **2026-11-17 Story 03.0 Task 01 (as built, macOS-verified).** `stage.py package` with `scripts/ci/package_archive.py` and `.github/workflows/stage-package.yml` is in place. Both 2026-11-16 rulings are applied. (1) Packaging legs ship `Release`, which differs by design from C06's `-C Debug`. They now build in their own `build/<leg>` tree with `CMAKE_BUILD_TYPE`/`--config`, so a Ninja leg cannot ship its Debug tree under a `Release` label. (2) The archive holds libraries only, and both the stage and a test refuse the CLI/GUI. Locally: `ok: package macos-arm64: libbios-1.0.0-macos-arm64.tar.gz, 78 files, 838069 bytes, sha256 4d10fcb0965908ff, Release, macos_min 12.7`; the archive is byte-identical on a repeat run. **Wired the same day (second pass):** the `package` job is in `ci.yml` (`needs: [plan, build]`). The packaging legs build, test and install in the build matrix (`tiers.full` only, D7) and hand off one `install-<leg>.tar` each (P15 unchanged). The package stage downloads each by artifact ID and refuses a tree whose digest differs from the build job's per-leg output (CR-8). A manifest job merges the three parts into one `manifest.json`. **Release-only test bug found by this story, and fixed (2026-11-17).** Building the packaging legs `Release` immediately exposed a latent defect in `tests/c_abi/smbios_typed_getters_test.cpp`, which had only ever been built `Debug`: `NDEBUG` turns `assert(x)` into `((void)0)`, and the file relied on `assert()` in two different ways that both break under it.

   - **Calls written inside `assert()` never execute.** `smbios_entry_count()` and `smbios_entry_at()` were, so `count` stayed 0 and `entry` stayed `nullptr`. Four further sites (`smbios_system_uuid`, `smbios_memory_device_size` and two `smbios_bios_vendor` mismatched-type checks) were also inside `assert()`, so in Release those negative checks **silently did not run at all** - the quieter and more dangerous half of the bug, since the test still reported success.
   - **Unchecked errors leave out-parameters untouched.** In `fetch()` the calls were correctly outside the `assert()`, but dropping the error check let it build a string of length `needed - 1` with `needed == 0`, underflowing `size_t` - the observed `std::length_error: basic_string`.

   **As fixed:** all 8 `assert()` uses in that file became a `CHECK()` macro that survives `NDEBUG` (it reports the failed expression and `std::abort()`s), plus two explicit `needed > 0` guards in `fetch()` so the documented NUL-inclusive contract is enforced rather than assumed. The sibling `tests/c_abi/smbios_entry_iteration_test.cpp` already kept its calls outside `assert()` and needed no change. **A sweep of the whole tree for this bug class found no others:** every `assert()` in `libsmbios/src/` is a pure `!<map>_.empty()` check with no side effect, so product code was unaffected. Verified: the test passes in **both** configurations (Release `build/macos-arm64` and Debug `build/macos`), and Release now reports "mismatched-type checks passed", proving those checks execute. `stage.py test --leg macos-arm64` reports `tests unprivileged: 18 passed, 0 skipped, 18 total` (previously an abort), and `--leg macos-asan` still reports 18 passed plus 3 live-table.

   This is the first thing Release-configuration packaging bought: a test that had been reporting success while skipping its own negative assertions. It argues for widening Release coverage beyond the packaging legs, which C06's `-C Debug` does not give.
